# Lessons

- When a project specification (PRD, ADR, SDD) or user configuration explicitly declares an infrastructure dependency (such as MariaDB), do not unilaterally fallback or switch to an alternate system (like SQLite) merely because the service is offline or uninitialized; instead, spin up the required service (e.g. via Docker Compose / Docker container) or verify/restore the declared stack.
- When writing code, services, seeders, UI labels, document templates, or task artifacts, always use English exclusively and avoid mixing Indonesian or non-English terminology (such as "Surat Jalan" or local address/label terms), ensuring complete internationalization and consistency across the codebase.
- Do not bypass Composer platform checks by faking runtime extensions (e.g. `config.platform.ext-intl`) when the corresponding binary extension is absent from the host PHP runtime; Filament v3 and Laravel strictly require physical extensions like `php-intl` for `Number::format` and table pagination at runtime. Ensure the host packages (such as `php8.5-intl`, `php8.5-bcmath`, `php8.5-gd`) are installed and verified via `php -m`.
- When designing dark mode UI cards, containers, and bin layouts in Filament, do not rely on sharp wireframe borders on black canvases; use solid elevated grayish surface backgrounds (e.g. gray-800 / zinc-800 fills) with borderless styling so sections stand out through surface contrast rather than stark line outlines.
- In Filament Resource forms and table columns, never assume standard column names (e.g. `order_number`) when referencing related models such as `DeliveryOrder` (which uses `do_number`); verify the model's schema migrations and prefer idiomatic Filament relationship components (e.g. `->relationship('deliveryOrder', 'do_number')`) with Livewire feature tests covering both Create and List pages to guard against `QueryException` regressions.
